# Статус проекта InternetRadio

Модуль проигрывания интернет-радио на C# (netstandard2.0, без внешних зависимостей,
без привязки к Unity).

## Что реализовано и работает

### 1. Декодер MP3 (`Mp3Decoder`)
Собственный скалярный порт public-domain алгоритма [minimp3](https://github.com/lieff/minimp3) (CC0).
Поддерживается MPEG-1/2/2.5 **Layer III**: моно, стерео, Joint Stereo (M/S + intensity),
короткие блоки, битовый резервуар.

**Валидация:**
- побитово идентичен эталонному minimp3 (собран оригинальный C через tcc, `max diff = 0`);
- на 146-секундном музыкальном MP3 320 кбит/с: корреляция **0.99999999997** с ffmpeg,
  макс. расхождение **2 LSB**, отношение сигнал/ошибка **−102.7 дБ**, длина выборки
  совпадает (кадры не терялись и не дублировались);
- чистый синус декодируется с THD ≈ −95 дБ.

### 2. Стриминг (`StreamClient`, `IcySplitter`)
- сырой TCP (+TLS через SslStream), ручной разбор статус-строки `ICY 200 OK` /
  `HTTP/1.0 200 OK` и заголовков;
- разбор in-band ICY-метаданных (`StreamTitle`, UTF-8);
- **HTTP-редиректы (302)** — до 10 переходов;
- автопереподключение при обрыве.

### 3. Буферизация
- `RingBuffer` — потокобезопасный кольцевой буфер (по умолчанию 1 МБ);
- пребуфер перед стартом декодирования (по умолчанию 128 КБ ≈ 8 с аудио);
- `WaveOutPlayer` — 24 буфера ≈ 0.6 с между декодером и звуковым устройством.

### 4. Публичный API (`InternetRadio`)
`SetUrl` / `Start` / `Stop` + события `PcmDecoded` (PCM 16 бит, interleaved),
`StreamTitleChanged`, `StateChanged`, `Error`. Кроссплатформенный, без Unity-зависимостей.

### 5. Тестовый плеер (`tests/InternetRadio.Tests`)
- `decode <mp3> <pcm>` — офлайн-декодирование файла;
- `chunk <mp3> <pcm> <размер>` — декодирование файла порциями заданного размера
  (регресс-тест потокового пути декодера: результат обязан совпадать с `decode`);
- `live <url> <сек> <wav>` — запись потока в WAV;
- `play <url> <сек>` — живое проигрывание на Windows (waveOut/winmm) + диагностика;
- `wavplay <file.wav> [сек]` — проигрывание локального WAV тем же плеером (изоляция
  уровня воспроизведения от сети/декодера; логирует позицию устройства `waveOutGetPosition`
  и дрейф позиции относительно настенных часов).

Проверено на станциях: `http://195.91.237.50:8000/ices128` и
`http://myradio24.org/ussr` (обе — MP3 128 кбит/с, 44.1 кГц, Joint Stereo M/S).

## Найденная и исправленная проблема

**Симптом:** при проигрывании «перескоки вперёд без тишины», как будто из аудио вырезают
небольшие порции (звучит как ускорение). Первые ~4 с (пребуфер) — чисто.

**Первопричина:** баг в потоковом пути `Mp3Decoder`. Декодер битово точен на целом файле,
но при подаче порциями (как в живом потоке — кольцевой буфер читается кусками 8 КБ, и
ICY-сплиттер дробит их на стыках метаданных) **терял MP3-кадры**. Внутренний цикл
`DecodeAvailable` при «кадр ровно заполнил буфер» ошибочно оставлял хвост из 4 байт,
сбивая выравнивание потока и заставляя ресинхронизатор пропускать следующий кадр. Потери
росли с уменьшением размера порции (8 КБ → −25 %, 4 КБ → −50 %, ≤1 КБ → 100 %).

**Исправление (все в `Mp3Decoder`):**
- `DecodeAvailable`: при успешном декодировании кадра всегда потреблять ровно `frame_bytes`
  (в т.ч. когда кадр заполнил буфер целиком), а хвост из 4 байт оставлять только в случае
  «синхронизация не найдена»;
- быстрый путь (`DecodeFrame`): на известной границе кадра при неполном кадре **ждать**
  (`FrameBytes = 0`), а не уходить в ресинхронизацию;
- `Mp3dFindFrame`: при валидном заголовке с неполным кадром пропускать мусор до него и
  ждать; принимать полный кадр в начале буфера, когда заголовок следующего ещё не пришёл.

**Проверка:** `decode` и `chunk` (размер порции 100 Б…8 КБ) дают **побайтово одинаковый**
PCM (MD5 совпадает); живой захват 30 с теперь даёт ~32.6 с звука (ранее «нестабильная
отдача» ~59 % была на самом деле потерей кадров в декодере). **Подтверждено на слух на
устройстве: проигрывание звучит корректно, без заметных артефактов.** ✅

Сопутствующие улучшения воспроизведения (не были первопричиной, но полезны):
- `WaveOutPlayer` пополняется по событию `CALLBACK_EVENT`, а не опросом `Thread.Sleep(1)`;
- PCM агрегируется в блоки ~100 мс (вместо 26 мс на кадр);
- `TcpClient.ReceiveBufferSize` = 1 МБ (`InternetRadio.SocketReceiveBufferBytes`);
- приоритет потока декодера `ThreadPriority.AboveNormal`.

### Изоляция модулей (итог)

1. **Декодер (файл целиком)** — битово совпадает с ffmpeg, кадры не теряются. ✅
2. **Декодер (потоково, порциями)** — после исправления побайтово совпадает с цельным
   декодированием для порций 100 Б…8 КБ. ✅
3. **Данные с радио** — живой захват даёт непрерывный корректный WAV (32.6 с за 30 с
   стены, т.е. ~реальное время с учётом пребуфера). ✅
4. **Воспроизведение** — проверить на слух на устройстве (`play`/`wavplay`); при
   остаточных артефактах — смотреть `drift` позиции устройства в `wavplay`.

## Сборка и проверка

```powershell
dotnet build InternetRadio.sln -c Release

# живое проигрывание (Windows):
dotnet run --project tests\InternetRadio.Tests -c Release -- play http://myradio24.org/ussr 30

# запись в WAV:
dotnet run --project tests\InternetRadio.Tests -c Release -- live http://myradio24.org/ussr 15 out.wav
```
